01 / START WITH THE BUSINESS

Care about the outcome.
Make the requirements explicit.

↗

How fast should it feel?

Define response time, acceptable freshness, and how long a customer can wait for a final result.

↻

What must never go wrong?

Make duplicate side effects, lost work, ordering, and availability requirements part of the connection.

⌁

What matters most?

Set the priorities for each edge: correctness, latency, availability, simplicity, and cost.

You define what the business needs. Plug derives the integration design from those requirements and the system facts.

02 / THE WORKFLOW

Draw the workflow.
Define the experience.

A system is more than its APIs. Plug makes the requirements between them part of the design.

  1. 01 / CONNECT

    Add vendor endpoints

    Bring operations from your systems and different vendors into one workflow graph.

    Endpoints become nodes
  2. 02 / DEFINE

    Set QoS on each edge

    Specify response time, freshness, reliability, and the tradeoffs your business accepts.

    Connections carry intent
  3. 03 / DERIVE

    Review the design

    Plug checks the facts, composes integration patterns, and explains each recommendation.

    Decisions have reasons
  4. 04 / BUILD

    Connect your IDE

    Expose the spec through MCP so your coding agent can read and update the system design.

    Intent stays with the code

Plug derives designs deterministically. Unknown facts stay unknown, and analysis never invokes your endpoints.

03 / FROM DESIGN TO CODE

Your system design.
In your agent’s context.

Plug exposes your workflow and its requirements through an MCP server. Add it to your agentic IDE so the agent can consult the design before changing an integration.

The workspace spec and agent instructions carry your intent into implementation. When an integration changes, the agent can update the spec and ask Plug to re-analyze it.
